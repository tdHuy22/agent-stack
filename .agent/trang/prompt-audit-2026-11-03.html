Chữ cấu hình nạp vào mỗi phiên Claude Code còn hợp với model hiện tại không?

Tóm tắt

Mỗi phiên Claude Code mở trong project này đều đọc sẵn một số file chữ hướng dẫn. Mình soát các file đó theo một quy trình kiểm có sẵn của Anthropic, tìm ba loại lỗi: câu viết cho model đời cũ, sự kiện đã sai so với code, và hai file nói ngược nhau. Ba file hướng dẫn bạn tự viết không có câu sai nào: mọi đường dẫn và lệnh chúng nhắc tới đều còn đúng; chỉ có hai câu kể lịch sử nên bỏ, đã viết sẵn thành thay đổi đề xuất, chưa áp dụng. Các phát hiện còn lại nằm trong gói mở rộng đã cài, chỉ được báo. Bạn cần quyết ba việc ở cuối trang.

Từ gốc

Cái gì được kiểm

Mỗi khi mở phiên Claude Code trong thư mục agent-stack, công cụ nạp sẵn một số file chữ vào đầu cuộc trò chuyện: file hướng dẫn của project (CLAUDE.md), file hướng dẫn chung cho mọi project (~/.claude/CLAUDE.md, thực ra là liên kết tới global/CLAUDE.global.md trong repo này, và file đó nhập thêm global/SHARED.global.md), cùng phần mô tả của mọi skill và subagent từ các plugin đã cài. Nội dung đầy đủ của một skill chỉ được nạp khi skill đó được gọi.

Bản kiểm theo hướng dẫn prompt-audit của skill claude-api, tài liệu Anthropic đi kèm Claude Code. Nó liệt kê các mẫu chữ đã biết là hợp với model cũ nhưng gây hại cho model mới (ví dụ chữ in hoa kiểu PHẢI, KHÔNG BAO GIỜ làm model mới áp dụng quá tay), cùng danh sách những thứ không được xoá. Model đích là Opus 5.5, model đang chạy phiên này. Câu hỏi cho mỗi dòng: dòng này chặn một lỗi nào, trên model nào, và lỗi đó còn xảy ra trên Opus 5.5 không. Độ dài không phải lý do để xoá; ngữ cảnh chỉ tác giả biết (luật của bạn, lý do, sự kiện về máy) luôn giữ.

Vấn đề hôm nay

Chữ cấu hình tích tụ theo thời gian. Ví dụ thật: CLAUDE.md:38 vẫn ghi nhánh trien-khai-v1 "đã gộp và xoá ngày 03/10/2026". Câu đó không còn điều khiển hành vi nào, nhưng model hiện tại đọc chữ rất sát nghĩa, nên mỗi câu thừa là một thứ nó phải cân nhắc. Nghiêm trọng hơn là khi hai file nói ngược nhau: model không biết file nào mới hơn.

Cần biết trước

  1. Mức tin cậy: cao là repo chứng minh được (đường dẫn không tồn tại, hai luật ngược nhau, công cụ báo khác); vừa là mẫu đã biết gây hại; thấp là dựa vào kiểu chữ, chỉ nêu, không sửa. Cần để đọc bảng phát hiện.
  2. Hành động: sửa (có chữ thay thế), bỏ, hay nêu (không đề xuất sửa, cần bạn quyết hoặc nằm ngoài phạm vi sửa). Cần để biết phát hiện nào có trong bản vá.
  3. Phạm vi sửa: chỉ file trong project được vá. File plugin đã cài và file ngoài project chỉ được báo. Riêng hai file trong global/ nằm trong project nhưng nạp vào mọi project, nên sửa ở đó ảnh hưởng mọi project.

Ví dụ 3 · Plugin dùng tham số công cụ đã cũ

project-artifact/SKILL.md:79   `favicon` = one or two emoji …
project-artifact/SKILL.md:101  … WebFetch the URL to see the current content

Artifact là trang web riêng tư trên claude.ai do Claude đăng. Công cụ đăng trang hiện tại đánh dấu tham số favicon (biểu tượng trên tab, bằng emoji) là đã bỏ, thay bằng icon nhận một từ như "chart" hay "map". Hậu quả: khi skill này chạy, Claude làm theo chữ cũ và có thể truyền tham số bị bỏ qua. Công cụ cũng yêu cầu đọc trang Artifact bằng action: "read" chứ không qua WebFetch. Đây là plugin chính thức của Anthropic, nên chỉ báo; bản sửa phải đến từ bản plugin mới.
