# Sửa mutation.py (done-gate): bản vá nhiều file lệch dòng, quá giờ không báo phần chưa chạy · mức cao (done-gate chạy lệnh test) · GĐ6, threat model TM-129
S1: Khi diff có từ hai file Python đổi trở lên, thì mỗi đột biến nằm trên một dòng thêm (theo `git diff -U0`) của chính file chứa nó, và mỗi file có dòng code thêm đều được đột biến, kể cả file nằm trong thư mục tên `a` hay `b`.
S2: Khi mutmut báo một đột biến ở file hay dòng không thuộc dòng thêm, thì kết quả ghi riêng đột biến đó là "ngoài dòng đổi" kèm file:dòng (JSON `outside`; output chữ có một dòng cảnh báo), để bản vá lệch không bị coi là kết quả thật.
S3: Khi không nêu `--jobs` mà diff có từ 20 dòng code Python thêm trở lên (dòng code là dòng thêm không trống và không chỉ có chú thích), thì mutation.py chạy min(4, số lõi/2, số dòng code thêm/10) lần mutmut song song. Mỗi lần chạy trong một bản chép riêng ở thư mục tạm, mỗi dòng thêm thuộc đúng một lần chạy, rồi kết quả được cộng lại. Diff nhỏ hơn thì gọi `mutmut run` đúng một lần như cũ.
S4: Khi nêu `--jobs N`, thì số lần chạy là min(N, số dòng code thêm), và N=1 là một lần chạy như cũ. N không phải số nguyên dương thì thoát 0 với "chưa chạy: tham số sai".
S5: Khi hết giờ, thì mọi lần chạy song song bị giết cả nhóm tiến trình, mọi bản chép bị xóa, và file đang bị đột biến dở (còn `<file>.bak` trong bản chép) được trả về bản gốc trước khi đọc kết quả.
S6: Khi còn đột biến chưa chạy tới, thì kết quả liệt kê vị trí của chúng theo file, gộp thành khoảng dòng (JSON `unreached`), và ước số giây còn cần với cùng số lần chạy (JSON `estimate_seconds`; output chữ gợi ý `--timeout`). Nếu `junitxml` hỏng, kết quả ghi rõ không lấy được vị trí.
